# 一个正分母为什么仍会“无法出证”？

中文 | [English](README.en.md)

## 运行

需要 Python 3，仅使用标准库。在本目录运行：

```sh
python exact_boundary_core.py
```

本次整理已原样提取完成记录里的代码，并实际运行，输出如下：

```text
positive denominator at 96 bits: [0, 1/2**96]
exact independent certificate: SAFE, [-0.005384615385, -0.005384615384] ppm
exact certificate width is below 4e-30 ppm
PASS: Fraction decisions; no numerical integration or external files.
```

## 问题与输入

恒星半径归一化为1。行星半径 k=1/100，圆心距离 z=99/100+2⁻¹²⁰，亮度为 p(r)=1−cr²，其中 c=7/10。这是 α=2 的特殊模型。偏移极小，普通 binary64 在该位置不能把它作为独立偏移保留。

程序先精确计算正分母 (z+k)²−1，再模拟96位二进制网格的向外包围。结果是 [0,2⁻⁹⁶]。因此“包围包含零”并不能说明原数等于零；依赖该区间作除法的认证路线可能拒绝继续。

## 独立检查的思路

对二次亮度，多项式在整个行星圆盘上的积分可通过圆盘矩精确求出。落在恒星外的极小部分，则用厚度 ε=z+k−1 的窄环带面积上界控制。设 d=1−c/2，J 是代码中固定生成的 binary64 亮度值，有

```text
R_full = 10^6 k² [1 − c(z² + k²/2) − J] / d
|R_J − R_full| ≤ 10^6 [(1+ε)² − 1] max(|J|, |1−J|) / d
```

所有判定用 Fraction 精确运算。打印的小数只是向外取整展示；实际分数区间宽小于 4×10⁻³⁰ ppm。SAFE 在这里只表示该区间被包含于 [−1,1] ppm。
